Why not accuracy? With an {{ pct(tm.base_rate, 1) }} subscription rate, a model that always says “no” is {{ pct(1 - tm.base_rate, 0) }} accurate and useless. We judge ranking (ROC-AUC, PR-AUC), probability honesty (Brier, calibration error) and what the decisions achieve (Decision policy page).

Was the 1D CNN justified?

The original project fed a one-hot vector ({{ k.input }}) into convolution filters. Convolutions assume that neighbouring inputs form local patterns, as pixels do. Here the neighbours are just the order of the columns. Test: retrain with the columns randomly shuffled.

How explanations are computed

  • Local (per lead): exact TreeSHAP (Lundberg et al., 2020). Each field gets a contribution in log-odds; contributions + the average-lead baseline add up to the lead's estimate. Verified on every training run: max additivity error {{ "%.1e" | format(card.shap_additivity_max_error) }}.
  • Global: mean |SHAP| across held-out leads, plus the average effect of each value (Interaction patterns page).
  • Interactions: SHAP interaction values and an additive-vs-full model comparison.
  • Counterfactual: the what-if simulator re-scores an edited lead with the same model and shows which contributions moved.
  • A pitfall we caught: SHAP silently returns wrong values for scikit-learn boosting with native categorical splits (error 2.7 log-odds). Categoricals are therefore ordinal-encoded, and a test guards against regressions.
